# 방법론 선택

> 생성: 2026-06-27 | PreFlight Phase 3

---

## 목표 전체 재분해 (구체적 하위 목표로 분리)

통합 시스템은 단일 목표가 아닌 **4개의 독립 목표**로 분리 가능. 각각 다른 방법론이 적합.

---

## 목표 A: Consilium HTTP Bridge 플러그인 (openclaw ↔ Consilium)

**목표**: openclaw 플러그인에서 Consilium REST API (`/api/debates`, `/api/goals`, `/api/self-dev/tasks`)를 호출해 채널 명령을 루프 엔지니어링으로 전환.

| 항목          | 내용                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------- |
| 작업 성격     | HTTP 클라이언트 래퍼 — 로직 단순, API 계약 이미 존재                                                             |
| 추천 방법론   | **Spike → TDD** — Consilium 로컬 서버 가동 + 수동 API 호출로 연동 가능성 먼저 증명. 성공 시 TDD로 플러그인 구현. |
| 산출 아티팩트 | 스파이크: curl/httpie로 API 연동 증명 스크린샷 / TDD: `extensions/consilium-bridge/src/index.ts` + 테스트        |
| AutoPM 신호   | **스파이크 우선** → 성공 확인 후 TDD 게이트 적용                                                                 |
| 예상 LOC      | 플러그인 본체 ~300줄, 테스트 ~150줄                                                                              |
| 위험          | Consilium 서버가 항상 실행 중이어야 함 → 상태 체크 필수                                                          |

---

## 목표 B: Ollama 공급자 플러그인 (openclaw 네이티브 Ollama 지원)

**목표**: openclaw에서 Ollama 모델을 직접 공급자로 사용 가능하게 하는 `extensions/ollama` 플러그인.

| 항목          | 내용                                                                  |
| ------------- | --------------------------------------------------------------------- |
| 작업 성격     | 기존 공급자 플러그인 패턴 복사 (anthropic, openai 플러그인 참조)      |
| 추천 방법론   | **TDD** — 공급자 계약이 명확함(`src/llm/providers/` 인터페이스 기반)  |
| 산출 아티팩트 | `extensions/ollama/src/index.ts` + provider manifest + 테스트         |
| AutoPM 신호   | TDD 게이트 9/10 적용                                                  |
| 예상 LOC      | ~400줄 (기존 groq 플러그인 참조, 구조 동일)                           |
| 위험          | 공급자 인터페이스가 버전마다 다를 수 있음 → 현재 `main` 기준으로 작성 |

---

## 목표 C: 프롬프트 인젝션 가드 미들웨어

**목표**: DisBot의 20+ 인젝션 패턴을 openclaw 플러그인 SDK의 `beforeMessage` 훅에 적용.

| 항목          | 내용                                                                                |
| ------------- | ----------------------------------------------------------------------------------- |
| 작업 성격     | 정규식 패턴 포팅 (Python → TypeScript) + 훅 등록                                    |
| 추천 방법론   | **TDD** — 각 패턴에 대한 단위 테스트가 핵심                                         |
| 산출 아티팩트 | `extensions/security-guard/src/patterns.ts` + `index.ts` + 테스트 (패턴당 1 테스트) |
| AutoPM 신호   | TDD 게이트 9/10 적용. 패턴 포팅은 표 드리븐 테스트로.                               |
| 예상 LOC      | ~200줄 (패턴 20개 × 3줄 + 훅 등록)                                                  |
| 위험          | 정규식 특수문자 Python↔JS 차이 (특히 `\b`, `(?i)` 등) → 패턴별 검증 필수            |

---

## 목표 D: 감사 로그 SQLite 스키마 + Loop 스케줄러

**목표**: 루프 엔지니어링 세션의 감사 로그를 openclaw SQLite에 저장 + openclaw cron으로 주기적 루프 실행.

| 항목          | 내용                                                                 |
| ------------- | -------------------------------------------------------------------- |
| 작업 성격     | DB 스키마 설계 + cron 등록                                           |
| 추천 방법론   | **OOD(객체 설계) → TDD** — 스키마 먼저 확정 후 Kysely 헬퍼 작성      |
| 산출 아티팩트 | `src/schema/loop-audit.ts` (Kysely 테이블 정의) + cron 등록 테스트   |
| AutoPM 신호   | OOD 모델링 1일 → TDD 게이트                                          |
| 예상 LOC      | ~150줄                                                               |
| 위험          | openclaw SQLite 마이그레이션 패턴을 따르지 않으면 doctor 시스템 충돌 |

## 전체 실행 순서 (권장)

```
[스파이크] Consilium API 연동 증명 (½일)
      ↓ 성공 시
[목표 B] Ollama 플러그인 TDD (1-2일)
      ↓
[목표 A] Consilium-Bridge 플러그인 TDD (2-3일)
      ↓
[목표 C] 보안 가드 포팅 TDD (1일)
      ↓
[목표 D] 감사 로그 + 스케줄러 (1일)
      ↓
[E2E 검증] 명령 → 토론 → 코드 → 검증 전체 흐름
```

**총 예상 기간**: 6-8일 (단독 개발 기준)
**MVP 기간**: 스파이크 + 목표 A + B만으로도 핵심 가치 증명 가능 (3-4일)
