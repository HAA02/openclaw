## 목표 A: Consilium Bridge 플러그인

| 도전                                                                                                                                             | 심각도 | 완화책 / STOP                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **"Consilium 서버가 항상 켜져 있다"는 가정** — 로컬 PC에서 FastAPI 서버가 항상 실행 중이어야 함. 재시작 시, 충돌 시 openclaw는 무응답 상태가 됨. | 🔴     | **완화**: Bridge 플러그인에 Consilium 상태 체크(`GET /api/health`) + 서버 다운 시 명확한 에러 메시지 반환. 자동 재시작은 별도 프로세스 매니저(pm2/systemd) 필요 — 범위 외로 분리. |
| **TypeScript ↔ Python 스택 경계** — 두 프로세스 간 직렬화 에러, 타임아웃, 네트워크 지연이 사용자 경험 저하. 특히 토론 루프는 수 분 소요 가능.    | 🔴     | **완화**: 비동기 SSE 스트림 활용 (`GET /api/debates/{id}/stream`). openclaw가 스트리밍 결과를 채널에 점진적 전달. 동기 폴링 금지.                                                 |
| **Consilium Goal API가 완성됐다는 가정** — Cycle 6 완료지만, API 계약이 변경될 수 있음 (Consilium은 사용자 소유 repo라 언제든 바뀜).             | 🟡     | **완화**: Bridge 플러그인에 Consilium API 버전 핀 + 명시적 에러 처리. API 계약 변경 시 Bridge만 수정하면 됨.                                                                      |
| **루프가 무한 실행될 수 있음** — Goal 루프가 실패 → 재시도 → 에스컬레이션 → 또 재시도. 사용자가 중단하지 않으면 Ollama GPU를 24시간 점유.        | 🔴     | **완화**: 명시적 `max_iterations` 파라미터 강제 + openclaw 채널에서 `/loop-stop` 명령 지원. 완화 없으면 **STOP 후보**.                                                            |

## 목표 B: Ollama 공급자 플러그인

| 도전                                                                                                                                                      | 심각도 | 완화책 / STOP                                                                                                                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ollama 모델 품질 vs Claude의 품질 차이** — 로컬 LLM(예: llama3, qwen2.5-coder)이 Claude Sonnet 수준의 코드 생성을 못 하면 루프가 의미 없는 출력을 반복. | 🔴     | **완화**: Ollama는 "무비용 빠른 반복" 역할로 한정. 검증 단계(`verify_cmd`)에서 실제 코드 실행으로 품질 평가. 루프가 N회 이상 실패 시 사용자에게 Claude 공급자로 전환 제안. |
| **로컬 GPU 메모리 부족 (OOM)** — 24시간 루프 중 Ollama가 OOM으로 충돌하면 전체 파이프라인 중단.                                                           | 🔴     | **완화**: Consilium의 `gpu_guard` 추론 잠금 메커니즘 [코드:Consilium/src/inference_lock.py] 참고. Bridge 플러그인에서 동시 Ollama 호출을 1개로 제한.                       |
| **openclaw 공급자 인터페이스가 내부 API** — CLAUDE.md에 "core stays plugin-agnostic" 원칙 있으나, 공급자 인터페이스가 semver 없이 변경될 수 있음.         | 🟡     | **완화**: 플러그인을 공개 SDK 배럴(`api.ts`, `runtime-api.ts`)에만 의존. 내부 `src/llm/providers/` 직접 참조 금지.                                                         |

## 통합 아키텍처 전체에 대한 도전

| 도전                                                                                                                                                                    | 심각도 | 완화책 / STOP                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **"전부 다 합치면 더 좋다" 범위 크리프** — 목표 A+B+C+D를 동시에 만들려다 아무것도 완성 못 할 위험. 특히 세 개의 다른 코드베이스를 동시에 이해해야 함.                  | 🔴     | **완화**: **MVP = 목표 A(Bridge) + 목표 B(Ollama)만 먼저**. C(보안 가드)와 D(감사 로그)는 MVP 동작 확인 후.                                                                                                                                        |
| **openclaw가 upstream fork — PR 머지 충돌** — openclaw 원본에 새 PR이 머지되면 사용자 플러그인과 충돌 가능.                                                             | 🟡     | **완화**: 새 플러그인을 `extensions/` 하위에 독립 패키지로 분리 (core 직접 수정 최소화). upstream rebase 시 플러그인만 재연결.                                                                                                                     |
| **"24시간 자율 개발"이 실제로 유용한 결과를 낸다는 가정** — Consilium의 자가개발 루프가 검증(`verify_cmd`)을 통과하더라도, 생성된 코드가 사용자가 원하는 것인지는 별개. | 🔴     | **완화**: 루프 완료 시 사용자에게 diff 리뷰 채널 전송 + 명시적 승인(approve/reject) 요구. **auto-merge 절대 금지**. Consilium도 동일 원칙 (`On pass → return final diff for user approval (no auto-merge)` [코드:Consilium/src/repo_heal_loop.py]) |
| **세 프로젝트의 "최신 상태" 동기화** — 사용자가 Consilium을 업그레이드하면 Bridge API 계약이 바뀔 수 있음. 유지보수 부담 증가.                                          | 🟡     | **완화**: Bridge 플러그인에 Consilium API 버전 체크 엔드포인트 추가. 버전 불일치 시 명확한 에러로 알림.                                                                                                                                            |
