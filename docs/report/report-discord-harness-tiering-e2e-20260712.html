04 · 핵심 발견
위임 환각 (Delegation Hallucination)

CTO와 PM이 각각 "위임 완료"를 자신 있게 — 상세한 표까지 곁들여 — 보고했지만, 실제로는 sessions_spawn 도구 호출이 발생하지 않은 경우를 두 차례 독립적으로 잡아냈다. 세 가지 독립 증거로 대조 검증했다:

도구 정책 로그게이트웨이 journaltool policy removed ... via subagent tools.deny

05 · 하네스 v2
적용한 수정과 검증 결과

CTO/PM 채널 systemPrompt에 "위임 실측 규칙"을 추가했다 — "sessions_spawn 결과(runId)를 실제로 받기 전까지 위임했다고 말하지 마라. runId 없는 위임 서술 금지" + PM에는 파일 소유권 경계(src/**/public/** 직접 작성 금지) 규칙을 추가. 소규모 프로젝트(정적 팀소개 페이지)로 재검증했다.

✅ 환각 방지 — 2/2 검증됨

CTO는 이후 실제 runId(a86e0632)를 받은 뒤에만 위임 완료를 보고했고(tool-policy 로그 + activeSessions로 즉시 대조), PM도 더 이상 가짜 서브에이전트 서사를 만들지 않고 "내가 직접 만들었다"고 담백하게 보고했다. 이건 확실한 개선이다.

❌ 위임 강제 — 여전히 뚫림

SQLite subagent_runs.task 컬럼(CTO가 PM에게 실제로 보낸 텍스트, 정본)을 직접 조회한 결과: CTO가 "이 정도는 간단하다"고 스스로 판단해 채널 프롬프트의 "PM 운영 규칙"(frontend/security 강제 위임 문구) 문단을 통째로 프루닝하고 더 가벼운 자체 브리핑을 작성했다. 앞서 추가한 "완료 서술 금지" 규칙만 옮겨 적고, 역할 분업 강제 규칙은 빠뜨렸다.

패턴은 "작아서 생략"이 아니다 — 2,181줄짜리 대형 프로젝트에서도 PM은 동일하게 전부 혼자 구현했다. PM은 스폰·감독·통합의 조율 비용보다 직접 구현을 일관되게 선호한다. 프롬프트 문구는 지시이지 강제가 아니라서, opus급 모델이 스스로의 효율 판단으로 우회할 여지가 항상 남는다.

07 · 사용자 결정
구조적 강제 vs 프롬프트 유지

PM의 직접 구현 문제를 구조적으로 막는 방법(예: PM 채널에 tools.deny:["write","edit","apply_patch"]를 걸어 물리적으로 위임을 강제하거나, 별도 검증 게이트 에이전트를 추가하는 방법)을 제시했으나, 사용자는 "프롬프트 수정만 유지"를 선택했다. 산출물 품질은 이미 충분히 좋고(테스트 통과, 보안 GO), 가장 중요한 신뢰성 문제인 환각 방지는 해결됐다는 판단이다.

08 · 고도화 로드맵
다음에 개발할 것들
HIGH
PM 도구 스코프 제한 (구조적 위임 강제)

PM 채널에서 write/edit/apply_patch를 차단해 PM이 물리적으로 구현 파일을 쓸 수 없게 만든다. 선행 작업: PM 소유 문서(CONTRACT.md, package.json) 작성 경로 재설계, Bash 리다이렉트 우회 가능성 점검(exec sandbox 읽기 전용화 검토).

HIGH
자동 검증 게이트 에이전트

PM/CTO의 "완료" 보고를 상위 채널에 전달하기 전, subagents(action=list) 또는 SQLite subagent_runs 대조를 자동 수행하는 별도 감사 단계를 하네스에 추가 — 지금은 사람이 수동으로 3중 대조해야 실체를 알 수 있다.

MED
announce 재시도 정책 강화

모델 세션 한도로 완료 announce가 3회(~3분) 후 영구 소실되는 문제가 실제로 재현됐다. 고가치 완료 보고에 대해 더 긴 재시도 창 또는 영속 큐잉이 필요한지 config 스키마를 확인하고 반영.

MED
claude-cli 백엔드 관측 가능성 공백

OpenClaw 세션 .jsonl이 도구 호출(tool_use)을 기록하지 않고 최종 텍스트만 남긴다. 위임 여부 확인에 SQLite+게이트웨이 저널 수동 대조가 필요했던 근본 원인 — 세션 전사 자체에 도구 호출 이벤트를 남기는 방안 검토.

LOW
Discord 게이트웨이 하트비트 재연결 관찰

E2E 중 Gateway heartbeat ACK timeout이 간헐 발생(자기회복 확인됨, 조치 불필요). 빈도가 늘면 근본 원인 재조사.

09 · 방법론
서브에이전트 완료 주장 검증법

에이전트의 "위임/완료했다" 텍스트 주장은 그대로 믿지 않는다. 3종 세트 대조:

1. sqlite3 ~/.openclaw/state/openclaw.sqlite
   → subagent_runs 테이블: created_at / task_name / ended_reason / task(정본)

2. journalctl --user -u openclaw-gateway
   → "[agents/tool-policy] tool policy removed ... via subagent" 로그 존재 여부

3. "claude live session start ... activeSessions=N" 카운트 증가 여부

셋 중 하나라도 없으면 "위임했다"는 텍스트 주장은 거짓일 가능성이 높다.
